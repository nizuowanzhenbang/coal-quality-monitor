# 化验重评保留运输预警（2026-10-04）

原行为可在隔离 SQLite 实际接口复现：港口/入厂化验均正常，接收铅封损坏的严重运输预警后批次为 SEVERE；再次评估会删除该运输记录，批次变为 COMPLETED、预警数和风险归零，手动重算供应商信用分回到100。

## 修复后的行为

质量引擎仅替换八类自己生成的热值、灰分、硫分、水分、合同和综合预警。三类运输预警保留原ID、观测值、描述、创建时间、确认/解决/忽略状态、处理人、时间与备注。重复重评不增加运输记录；另一批次不受影响。

显式 flush 新质量记录后，按当前批次实际保存的全部预警计算状态、数量和风险。只有运输严重铅封预警时，重评仍为 SEVERE、数量1、风险0.60；按现有规则手动重算供应商为95分。一般运输超时预警时为 ALERT、数量1、风险0.15。质量与运输混合时同时计分；清除过时质量异常不会清除运输证据。

适用于手动评估、第二份化验录入后的自动评估及既有化验修改后的重评。评估响应的 `alerts` 和 WebSocket 推送继续只包含本次新生成的质量预警；`alert_count`、`status`、`risk_score` 包含两类预警。详情及预警列表用于查看全部记录。

处理状态的历史计分政策保持原样：已解决/已忽略的运输预警仍计入历史批次风险与供应商扣分。本轮不调整免责政策。预警替换和批次汇总在引擎原事务中提交，真实插入约束失败可回滚原预警与汇总。
